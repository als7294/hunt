# Vendor connectors: terms and prices on file

_Checked 2026-10-29 from the pricing page, the General Terms, the API docs and the Store API; prices confirmed by three live runs on 2026-10-30 (below). Prices change at the developer's discretion (Terms §7.1), so the per-post prices Hunt budgets with are settings, not code. Policy: [automation-legal.md](automation-legal.md) §4 ("vendor connector rules": optional, off by default, the investigator's own key, provenance per record, the vendor's permitted-use clause on file)._

## The line

Hunt ships no vendor key and runs completely free by default. When the investigator, or Ethos on her behalf, adds an Apify key in Settings, they accept Apify's terms below for that account, and the Actors' output is obtained under their account, not Hunt's. Every post so obtained is marked `origin: vendor`, named "Instagram (via Apify)" or "Facebook (via Apify)", and each run is in the audit log with vendor, Actor, build, run id, status, cost, account and time, so the report can say "N posts obtained through Apify under the investigator's own account". Media are fetched by Hunt from the platforms' CDNs and hashed here like every other evidence file.

## Apify

**Plan and credit** ([apify.com/pricing](https://apify.com/pricing)): the Free plan includes **$5 of platform usage a month, no credit card**. Pay-per-event Actors draw on that credit. Over the limit, "your access to Apify's services will be blocked until the beginning of the next monthly cycle"; unused credit expires with the cycle. Free-plan limits: 16 GB max RAM, 5 concurrent runs. Hunt reads the live figures from `GET /v2/users/me/limits` (`current.monthlyUsageUsd`, `limits.maxMonthlyUsageUsd`, `monthlyUsageCycle.endAt`) before every run and shows "this run ≈ $0.17 · about $4.10 of this month's credit left".

**Terms** ([Apify General Terms and Conditions, effective 2026-07-09](https://docs.apify.com/legal/general-terms-and-conditions)):
- §6.1: use the Services and Actors in compliance with the Acceptable Use Policy; §6.2: "process only the Customer Data that you are authorized to access".
- §5.8: the user is "solely responsible for the legality, accuracy, quality, appropriateness, and use of all Customer Data"; §9.1: the Data Processing Addendum applies to personal data in Customer Data, and Apify is "not responsible for your privacy obligations".
- §3.1: Store Actors "are not part of the Services provided by Apify" and come under the Actor Terms and the Store Publishing Terms; §7.1: Actor prices are set, and changed, by the Actor developer; §7.4: fees are non-refundable.
- §11.1: the user indemnifies Apify for data extracted "from unauthorized sources" and for disputes with Actor developers.

So the permitted-use question sits with the Actor developer's terms and the platform's, as the legal brief's decision tables put it (row (e), "vendor's risk" for Instagram, Facebook and TikTok). Ethos's counsel should see this page before a key is added.

**API used by `hunt/vendor.py`** ([docs](https://docs.apify.com/api/v2)): `POST /v2/acts/{actor}/runs` with the Actor input as the body and `maxTotalChargeUsd` ("the maximum total cost of the run… for all pricing models") and `timeout` as query parameters; `GET /v2/actor-runs/{id}?waitForFinish=60` until a terminal status (`SUCCEEDED`, `FAILED`, `TIMED-OUT`, `ABORTED`); the cost `usageTotalUsd` is read again about 10 s later, since the first figures after a run are preliminary; `GET /v2/datasets/{id}/items?clean=true`. The token travels in the `Authorization: Bearer` header, never in a URL.

**What the live runs charged (2026-10-30, `nasa`, 3 posts each, free plan):** Instagram detailed data: run `MRExCsiiqsFa5tixt`, $0.0081 (= $0.0027 a post); Instagram basic data: run `h7Thyt1j2SufLC3Co`, $0.0051 (= $0.0017 a post, carousel reduced to its cover); Facebook: run `5voLixYIDcbXGtVd3`, $0.016 (= 3 × $0.005 + $0.001 start). Items mapped (URL, date, caption, media), media downloaded and hashed (a 41 s reel, carousel pictures, Page photos), each run's cost audited. Total spent for the checks: $0.029.

**Budget at the defaults** (`results_limit` 100 Instagram / 50 Facebook, `fresh_days` 7, `monthly_cap_usd` 5): the first read of an account costs about $0.27 (Instagram) or $0.35 (Facebook: 50 posts + the start fee); re-checks pass `onlyPostsNewerThan` the last read, so they cost only what is new; an account read in the last 7 days isn't run again unless asked. Two testers each opening three Instagram accounts and two Facebook Pages a month spend about $3.00 of the $5.00; at 100 Facebook posts it would be $4.40, which is why the Facebook limit is lower (a post there costs 2.6× an Instagram post, 3.3× with the date filter). From 80% of the cap, `plan()["why"]` adds a warning. Apify stops a single run at `maxTotalChargeUsd` = 1.25 × the estimate + $0.01, and Hunt refuses a run that would take the month past the cap or the plan's credit.

**Settings.** The key is `HUNT_APIFY_TOKEN`, pasted on the app's "Connect free keys" screen (`hunt/keys.py` keeps it in `HUNT_HOME/keys.json`, mode 600, and in the process environment; `vendor.py` declares it in `keys.EXTRA`). The rest (`actors`, `price_per_post`, `instagram_detail`, `monthly_cap_usd`, `results_limit` as a number or one per platform, `fresh_days`) live in `HUNT_HOME/vendor.json`, mode 600; `HUNT_APIFY_ACTORS` overrides the Actors. `vendor.shown()` gives them to the app with the key as a yes/no; `vendor.save_settings(**changes)` stores them. The key is never written into a case or an evidence bundle. A post Hunt Capture already holds (same URL, any source) isn't stored again; Facebook URLs are canonicalised as `facebook._canon` does, so a vendor post and the same post she views merge.

**Hard stops.** When the revocation watcher has stopped a platform (a checkpoint, an "automated behaviour" notice, a disabled account; `browser.stops()`, see `docs/capture.md`), `vendor.plan()` skips every account on it with "hard stop on Instagram since …: no vendor read; Hunt never uses a vendor to get around a block", until she resumes the platform from the app. The brief's rule: a vendor is never a fallback around a block.

**Watch (opt-in).** `vendor.set_watch(case, True)` turns the vendor on for a watched case (default off; audited `vendor watch`). Each scheduled check then calls `vendor.recheck`, which reads only posts newer than the last read, within `fresh_days` and the caps, and never runs past 80% of the month's cap unattended: it records `vendor watch skipped` and leaves the run for her to confirm in the app. `hunt/watch.py` calls it right after `recheck.run`, so new vendor posts go through the scan with the rest.

**Not built.** TikTok through a vendor (the logged-out page reads cover it), X, LinkedIn, any Actor that needs cookies or a login, and any shared or bundled key.
